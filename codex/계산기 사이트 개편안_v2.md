# coin.sykim.dev 투자 계산·시뮬레이션 사이트 개편 요청 V2.1

기존 `coin.sykim.dev` 사이트를 전면 개편해줘.

현재 사이트의 기존 기능과 코드를 먼저 분석하고, 정상적으로 동작하는 기능은 최대한 재사용하면서 점진적으로 개편한다.

사이트를 단순한 물타기/불타기 계산기에서 다음과 같은 서비스로 확장한다.

> **국내주식, 해외주식, ETF, 금, 비트코인 등 다양한 투자자산의 계산과 시뮬레이션을 로그인 없이 사용할 수 있는 투자 계산 도구**

사이트의 핵심 목적은 투자상품을 추천하거나 미래가격을 예측하는 것이 아니다.

사용자가 직접 입력한 투자조건을 기반으로 다음 경험을 제공한다.

**입력 → 계산 → 결과 → 계산 과정 → 조건 변경 → 시나리오 비교 → 그래프 → 비용/세금 → 최종손익 → 이해**

---

# 1. 핵심 설계 원칙

사이트를 다음 개념으로 분리해서 설계한다.

## Asset Type

무엇에 투자하는가?

- 국내주식
- 해외주식
- ETF
- 금
- 비트코인/가상자산
- 기타 투자자산

## Calculation Type

무엇을 계산하는가?

- 평균매입단가
- 목표 평균단가
- 추가매수 시뮬레이션
- 투자 수익률
- 목표가격
- 손실 회복률
- CAGR
- 복리
- 적립식 투자
- 목표자산
- 배당/분배금
- 포트폴리오 비중
- 리밸런싱
- 환율 투자손익
- ETF 보수
- 투자 세금
- 거래비용
- 세후 수익률

## Context / Rule

계산에 어떤 외부 조건이 적용되는가?

- 통화
- 환율 시점
- 거래단위
- 자산 precision
- 수수료
- 과세 국가/관할
- 과세연도
- 세금 규칙

핵심적으로 다음 구조를 지향한다.

```text
Asset Type
      │
      ▼
Calculation Type
      │
      ▼
Calculation Engine
      │
      ├── Exchange Rate Context
      ├── Fee Context
      └── Tax Rule
      │
      ▼
Result / Scenario / Chart
```

자산별로 동일한 계산기를 중복 구현하지 않는다.

# 2. 사이트 아이덴티티

핵심 메시지:

> **로그인 없이 바로 사용하는 투자 계산·시뮬레이션 도구**

보조 메시지:

> 국내주식부터 해외주식, ETF, 금, 비트코인까지. 투자 결과를 계산하고 조건에 따른 변화를 직접 비교해보세요.

사이트는 다음을 제공하지 않는다.

- 종목 추천
- 매수/매도 추천
- 미래가격 예측
- AI 투자추천
- 자동매매
- 투자자문

대신 다음을 제공한다.

- 투자 계산
- 목표값 역산
- 시나리오 비교
- 그래프 시각화
- 계산 과정
- 환율 효과
- 비용 효과
- 세금 계산
- 세전/세후 결과 비교
- 계산 원리

# 3. 로그인 및 데이터 저장

회원가입 및 로그인 기능을 만들지 않는다.

사용자는 사이트 접속 즉시 계산기를 사용할 수 있어야 한다.

가능한 계산은 브라우저에서 처리한다.

다음과 같은 투자정보를 서버 DB에 저장하지 않는다.

- 평균매입단가
- 보유수량
- 투자금
- 매수/매도가
- 환율
- 자산구성
- 목표가격
- 수익률

실제 구현이 이에 부합한다면 다음 내용을 사용자에게 안내한다.

> 입력한 투자정보는 서버에 저장되지 않으며 계산을 위해 브라우저 내에서만 사용됩니다.

계산 기록이 필요해지면 LocalStorage를 우선 검토한다.

# 4. Asset Type 모델

자산 종류를 계산 페이지에 하드코딩하지 않고 공통 모델로 설계한다.

예:

```text
DOMESTIC_STOCK
FOREIGN_STOCK
ETF
GOLD
CRYPTO
OTHER
```

Asset Type은 필요에 따라 다음 정보를 가진다.

```text
표시명
통화
수량단위
가격 precision
수량 precision
환율 적용 가능 여부
배당 적용 가능 여부
ETF 보수 적용 여부
세금 계산 가능 여부
```

향후 다음 자산을 추가할 수 있도록 확장 가능하게 설계한다.

- 은
- 채권
- REITs
- 기타 원자재
- 기타 가상자산

# 5. 자산별 특성

## 국내주식

기본 통화:

KRW

기본 수량단위:

주

평균매입단가, 수익률, 배당, 세금/비용 등의 기능과 연결한다.

## 해외주식

외화 가격과 원화 환산을 모두 지원한다.

예:

```text
매수가        150 USD
수량           10 주
매수환율     1,350 KRW/USD
```

외화 손익과 원화 손익을 구분한다.

## ETF

국내상장/해외상장을 구분할 수 있도록 설계한다.

지원 기능:

- 평균매입단가
- 수익률
- 배당/분배금
- 적립식 투자
- ETF 보수
- 해외 ETF 환율손익
- 적용 가능한 세금

## 금

지원 단위 예:

- g
- kg
- oz

금 ETF는 GOLD가 아니라 ETF로 처리한다.

## Crypto

높은 소수점 precision을 지원한다.

예:

```text
0.1 BTC
0.015 BTC
0.00000001 BTC
```

정수 단위 반올림을 강제로 적용하지 않는다.

---

# 6. 금융 계산 정밀도

금융 계산에서 JavaScript 부동소수점 오차를 고려한다.

계산용 precision과 화면 표시용 precision을 분리한다.

특히 다음 값은 높은 정밀도를 유지한다.

- 금액
- 평균매입단가
- 환율
- Crypto 수량
- 배당
- 수익률

Decimal 기반 계산 또는 이에 준하는 명확한 precision 정책을 검토한다.

# 7. 평균매입단가

사이트의 대표 계산기로 만든다.

입력:

- Asset Type
- 현재 평균매입단가
- 현재 보유수량
- 추가 매수가
- 추가 매수수량

출력:

- 새로운 평균매입단가
- 평균단가 변화액
- 평균단가 변화율
- 기존 투자금
- 추가 투자금
- 총 투자금
- 총 보유수량

계산 공식과 계산 과정을 함께 표시한다.

물타기/불타기는 별도 계산기로 분리하지 않는다.

# 8. 목표 평균단가

입력:

- 현재 평균단가
- 현재 수량
- 추가 매수가
- 목표 평균단가

출력:

- 필요한 추가수량
- 필요한 투자금
- 최종 평균단가

자산별 거래단위와 precision을 반영한다.

---

# 9. 추가매수 시나리오

사용자가 추가 매수수량 또는 투자금액을 변경했을 때 결과를 비교한다.

각 시나리오에 대해:

- 추가 투자금
- 새로운 평균단가
- 평균단가 변화
- 변화율

을 표시한다.

그래프를 함께 제공한다.

---

# 10. 수익 관련 계산

다음을 제공한다.

## 투자 수익률

- 투자원금
- 평가금액
- 평가손익
- 수익률

## 목표가격

평균단가 + 목표수익률 → 목표가격

반대 방향 계산도 지원한다.

## 손실 회복률

예:

```text
-10% → +11.11%
-20% → +25%
-50% → +100%
-80% → +400%
```

그래프로 시각화한다.

## CAGR

- 최초 투자금
- 최종 평가금액
- 투자기간

을 이용하여 CAGR을 계산한다.

# 11. 장기투자 계산

## 복리

입력:

- 초기 투자금
- 추가 투자금
- 기간
- 가정수익률
- 복리주기

'예상수익률'보다 **'가정수익률'**이라는 표현을 사용한다.

- 초기 투자금

## 목표자산 역산

목표금액을 달성하기 위해 필요한 월 투자금 또는 기간을 역산한다.

실제 시장 예측이나 Backtest와 혼동하지 않도록 한다.

# 14. Exchange Rate Context

환율은 단순한 하나의 숫자가 아니라 **시점이 있는 값**으로 설계한다.

최소 다음 개념을 구분한다.

```text
매수 환율
현재 평가 환율
매도 환율
```

예:

```text
매수일
2026-01-10

매수환율
1,350 KRW/USD

평가기준일
2026-09-27

평가환율
1,400 KRW/USD
```

---

# 15. 환율 입력 방식

1차 버전에서는 사용자가 환율을 직접 입력한다.

```text
매수 환율
[ 1,350 ]

현재/매도 환율
[ 1,400 ]
```

API를 사용하지 않아도 모든 계산 기능을 사용할 수 있어야 한다.

향후 환율 API가 추가되면 다음 UX를 고려한다.

```text
환율 입력 방법

● 직접 입력
○ 날짜로 조회
```

날짜 조회 선택 시:

```text
거래일
[ 2026-01-10 ]

참고환율
1,347.82 KRW/USD

[ 참고환율 적용 ]
```

API 조회 결과가 사용자의 입력값을 자동으로 대체하지 않고 사용자가 적용 여부를 결정하도록 한다.

---

# 16. 환율의 의미

같은 날짜에도 실제 거래환율과 참고환율이 다를 수 있다는 점을 고려한다.

예:

- 시장환율
- 기준환율
- 매매기준율
- 증권사 적용환율
- 은행 환전환율

따라서 API로 가져온 환율은 가능하면 **'참고환율'**이라고 표현한다.

다음 안내를 제공한다.

> 실제 거래에 적용된 환율을 알고 있다면 해당 값을 직접 입력하는 것이 가장 정확합니다.

환율 데이터의 출처와 기준시점도 가능하면 표시한다.

# 18. 세금·비용 카테고리

기존 사이트의 세금 계산 기능을 제거하지 않는다.

현재 구현을 먼저 분석하고 재사용 가능한 계산 로직을 확인한다.

메인 메뉴에 다음 카테고리를 추가한다.

```text
세금·비용

├ 투자 세금
├ 거래 수수료
└ 세후 수익률
```

세금은 단순히 수익률 계산기의 부가기능으로만 취급하지 않고 별도의 계산 영역으로 제공한다.

# 19. Tax Rule 모델

세금 규칙을 Asset Type에 직접 하드코딩하지 않는다.

별도의 Tax Rule 개념을 설계한다.

예:

```text
TaxRule

- 국가/과세 관할
- 과세연도
- Asset Type
- 상품 세부유형
- 거래/소득 유형
- 세율
- 기본공제
- 과세표준 계산방식
- 적용조건
- Rule Version
```

세법은 변경될 수 있으므로 계산식과 UI에 세율을 직접 흩어놓지 않는다.

세금 규칙을 중앙에서 관리할 수 있도록 한다.

---

# 20. 과세연도

세금 계산에서는 적용 기준연도를 반드시 명확하게 표시한다.

예:

```text
해외주식 세금 계산

과세 기준
대한민국 · 2026년 귀속
```

세법 변경 시 기존 연도의 계산 규칙과 새로운 연도의 계산 규칙을 구분할 수 있도록 설계한다.

---

# 21. 자산과 세금의 관계

Asset Type만으로 세금을 결정하지 않는다.

예를 들어 ETF라면 다음과 같은 추가 분류가 필요할 수 있다.

```text
ETF
 │
 ├ 국내상장
 └ 해외상장
```

필요한 경우 상품 세부유형을 추가할 수 있도록 한다.

세금 계산은 다음과 같은 Context를 이용한다.

```text
Tax Jurisdiction
+
Tax Year
+
Asset Type
+
Product Type
+
Income / Transaction Type
```

이 조건을 바탕으로 적용 가능한 Tax Rule을 결정한다.

---

# 22. 세금 계산 UX

세금 계산 화면에는 최소 다음을 명확하게 표시한다.

- 과세 국가/관할
- 과세연도
- 자산 종류
- 상품 유형
- 계산에 적용된 세율/공제
- 과세표준
- 추정 세금

결과에서는 계산 과정을 보여준다.

단순히

```text
세금: 500,000원
```

으로 끝내지 않는다.

가능하면

```text
총 손익
        ↓
필요경비/적용항목
        ↓
공제
        ↓
과세표준
        ↓
적용 세율
        ↓
추정 세금
```

처럼 사용자가 계산 원리를 확인할 수 있게 한다.

---

# 23. 세금 데이터 최신성

세금 계산은 다른 계산기보다 최신성이 중요하다.

세율과 과세규칙을 임의로 추정하거나 오래된 값을 그대로 사용하지 않는다.

세금 기능을 실제 구현하거나 업데이트할 때는 해당 국가의 공식 세무기관, 정부기관 등 신뢰할 수 있는 최신 자료를 기준으로 검증한다.

세금 규칙에는 가능하면 다음 메타데이터를 관리한다.

```text
적용연도
최종 검증일
근거 출처
Rule Version
```

사용자에게도 계산 기준연도를 명확하게 보여준다.

---

# 24. 거래 수수료

수익 계산에 거래비용을 선택적으로 반영할 수 있도록 한다.

입력 예:

- 매수 수수료
- 매도 수수료
- 기타 거래비용

수수료율 또는 실제 수수료 금액 입력 방식을 고려한다.

자동으로 특정 증권사의 수수료를 가정하지 않는다.

사용자가 실제 거래조건에 맞게 직접 입력할 수 있도록 한다.

---

# 25. 세전/세후 수익률

```text

     ↓
세전 손익
     ↓
환율 효과
     ↓
거래비용
     ↓
적용 가능한 세금
     ↓
```

```text

-50,000원

-XXX,XXX원

```

세금 계산이 적용되지 않는 조건이라면 무리하게 값을 만들어내지 않는다.

# API 및 시장 데이터 활용 전략

현재 `coin.sykim.dev`에서는 이미 외부 API를 이용하여 환율 및 시장가격을 조회하고 있다.

기존 API 연동 코드를 먼저 분석하고 정상적으로 동작하는 기능은 제거하거나 새로운 API로 임의 교체하지 않는다.

현재 사용 중인 데이터 소스는 다음과 같다.

## ExchangeRate.fun

환율 데이터 제공자로 현재 사용 중이다.

주요 용도:

- 현재 환율 조회
- 통화 변환
- 해외투자 원화 환산
- 해외자산 수익률 계산을 위한 참고환율 제공

현재 API는 시간 단위로 환율 데이터가 갱신되므로 화면에서 `실시간 환율`이라고 단정하지 않는다.

가능하면 다음과 같이 표현한다.

- 현재 참고환율
- 최근 업데이트 환율
- 기준시각 표시

API 응답에서 데이터 기준일 또는 갱신시점을 확인할 수 있다면 사용자에게 표시한다.

예:

현재 참고환율

USD/KRW
1 USD = 1,XXX.XX KRW

기준시각
YYYY-MM-DD HH:mm

출처
ExchangeRate.fun

환율 API의 값을 실제 증권사에서 사용자에게 적용된 거래환율과 동일하다고 간주하지 않는다.

실제 매수/매도 당시 적용환율을 알고 있는 사용자는 직접 입력할 수 있도록 한다.

따라서 환율 입력 UX는 다음 구조를 지향한다.

[직접 입력]

또는

[현재 참고환율 불러오기]

API에서 가져온 환율은 사용자가 수정할 수 있어야 한다.

향후 과거환율 API가 별도로 도입되거나 현재 API가 해당 기능을 지원하게 된다면 다음 기능을 추가할 수 있도록 Exchange Rate Provider를 추상화한다.

거래일 선택
→ 해당 날짜의 참고환율 조회
→ 사용자에게 조회값 표시
→ 사용자가 적용
→ Calculation Engine 전달

Calculation Engine이 ExchangeRate.fun API를 직접 호출하지 않도록 한다.

다음 구조를 지향한다.

ExchangeRateProvider
        ↓
ExchangeRate Context
        ↓
Calculation Engine

향후 API가 변경되더라도 계산 로직을 수정하지 않아도 되도록 한다.

---

# Gold API

금 및 기타 지원 자산의 시장가격 조회에 현재 사용하고 있다.

주요 용도:

- 금 현재가격
- 은 현재가격
- 지원되는 귀금속/원자재 가격
- 지원되는 Crypto 가격

Gold API가 제공하는 자산과 사이트에서 실제 지원할 자산을 분리한다.

API가 특정 자산을 제공한다고 해서 사이트 메뉴에 자동으로 추가하지 않는다.

Asset Type에서 지원하기로 결정한 자산만 Calculation Engine과 연결한다.

예:

Gold API
   ↓
MarketPriceProvider
   ↓
GOLD
SILVER (향후)
CRYPTO (필요 시)
   ↓
Calculation Engine

Gold API의 가격 데이터는 투자 판단을 위한 확정 가격이 아니라 계산을 돕기 위한 참고 시장가격으로 취급한다.

화면에서는 가능하면 다음 정보를 함께 표시한다.

금 현재 참고가격

XAU
$X,XXX.XX / oz

기준시각
YYYY-MM-DD HH:mm

출처
Gold API

사용자는 API 가격 대신 직접 가격을 입력할 수도 있어야 한다.

---

# 현재가격과 과거가격의 분리

시장가격 API에서는 다음 두 개념을 반드시 분리한다.

## Current Market Price

현재 또는 최근 시장가격을 계산기에 자동입력하기 위한 기능이다.

예:

금 현재가격
Bitcoin 현재가격
환율 현재값

현재 사용 중인 API를 우선 활용한다.

## Historical Market Price

특정 날짜 또는 시간의 시장가격을 조회하기 위한 기능이다.

예:

2025-01-01 금 가격
2026-03-20 Bitcoin 가격

Historical API에는 호출 제한이나 별도 비용이 발생할 수 있으므로 현재가격 조회와 같은 기능으로 취급하지 않는다.

무료 플랜의 호출 제한을 확인하고 불필요한 API 호출을 발생시키지 않는다.

---

# API Provider 추상화

Calculation Engine에서 특정 API 서비스명을 직접 참조하지 않도록 한다.

다음과 같은 Provider 계층을 고려한다.

MarketDataProvider
│
├ ExchangeRateProvider
│   └ ExchangeRate.fun
│
├ MetalPriceProvider
│   └ Gold API
│
└ SecurityPriceProvider
    └ 향후 국내/해외 증권 API

Calculation Engine은 Provider가 제공한 데이터를 입력값으로 받을 뿐 데이터가 어디에서 왔는지 알 필요가 없도록 한다.

이를 통해 향후

ExchangeRate.fun → 다른 환율 API

Gold API → 다른 금/원자재 API

로 변경되어도 계산식을 수정하지 않도록 한다.

---

# API와 직접 입력의 관계

외부 API는 Calculation Engine의 필수 의존성이 아니라 **입력 편의 기능**으로 취급한다.

기본 원칙:

직접 입력
    ↓
Calculation Engine

또는

External API
    ↓
참고값 조회
    ↓
사용자 확인/수정
    ↓
Calculation Engine

API 장애가 발생하더라도 사용자는 직접 가격이나 환율을 입력하여 계산기를 계속 사용할 수 있어야 한다.

API 요청 실패가 계산기 전체의 장애로 이어져서는 안 된다.

---

# API 호출 최적화

브라우저에서 동일한 시장 데이터를 불필요하게 반복 요청하지 않는다.

API의 데이터 갱신주기를 고려하여 적절한 캐싱 전략을 적용한다.

예를 들어 데이터가 시간 단위로만 변경되는 API라면 사용자가 페이지를 조작할 때마다 동일 API를 반복 호출하지 않는다.

필요한 경우 다음을 검토한다.

- 메모리 캐시
- LocalStorage 캐시
- 캐시 만료시간(TTL)
- 마지막 업데이트 시각 저장

다만 오래된 캐시 데이터를 현재 데이터처럼 표시하지 않는다.

캐시 데이터를 사용하는 경우 데이터 기준시각을 함께 표시한다.

---

# API 데이터 표시 원칙

API에서 조회한 값에는 가능한 경우 다음 정보를 함께 관리한다.

- Provider
- Symbol
- Value
- Currency
- Unit
- Data timestamp
- Retrieved timestamp

예:

MarketData

provider = GOLD_API
symbol = XAU
value = ...
currency = USD
unit = OZ
dataTimestamp = ...
retrievedAt = ...

환율:

ExchangeRate

provider = EXCHANGE_RATE_FUN
base = USD
quote = KRW
rate = ...
dataTimestamp = ...
retrievedAt = ...

`dataTimestamp`와 `retrievedAt`을 가능하면 구분한다.

API를 호출한 시간이 곧 시장 데이터의 기준시간이라고 가정하지 않는다.

---

# 가격 및 환율 데이터에 대한 안내

API에서 제공받은 시장가격과 환율은 참고값으로 제공한다.

사이트에서 다음과 같은 표현을 사용하지 않는다.

- 실제 거래가격
- 실제 적용환율
- 정확한 실시간 거래가격

대신 데이터 특성에 따라 다음과 같이 표현한다.

- 현재 참고가격
- 현재 참고환율
- 최근 업데이트 가격
- 기준시각

실제 금융기관, 증권사, 거래소의 체결가격 또는 적용환율과 차이가 있을 수 있음을 안내한다.

---

# API 변경/장애 대응

현재 사용 중인 API를 영구적으로 사용할 수 있다고 가정하지 않는다.

API 서비스가 다음과 같이 변경될 수 있음을 고려한다.

- 서비스 종료
- 요금제 변경
- Rate Limit 변경
- Response Schema 변경
- 지원 자산 변경
- CORS 정책 변경

따라서 API 호출부를 Calculation Engine과 분리하고 Provider 단위로 교체할 수 있도록 한다.

외부 API 장애 시:

API 조회 실패
    ↓
사용자에게 조회 실패 표시
    ↓
직접 입력 활성화
    ↓
계산 기능 정상 사용

구조를 유지한다.

---

# 개발 시 기존 API 분석

개편 작업을 시작할 때 기존 프로젝트에서 다음을 먼저 확인한다.

1. ExchangeRate.fun 호출 위치
2. Gold API 호출 위치
3. API 응답 데이터 구조
4. API 데이터를 사용하는 기존 화면
5. 환율 계산 방식
6. 금/은/Crypto 가격 변환 방식
7. API 호출 빈도
8. 캐싱 여부
9. API 실패 처리
10. CORS 처리
11. 현재가격 기준시점 표시 여부

정상적으로 동작하는 기존 API 연동은 이유 없이 다시 작성하지 않는다.

필요한 경우 기존 코드를 Provider 구조로 리팩터링한다.

# 향후 추가 API

현재 API에서 제공하지 못하는 기능이 실제로 필요해졌을 때만 새로운 API를 검토한다.

예:

- 국내주식 현재가격
- 해외주식 현재가격
- ETF 가격
- 종목검색
- 과거 환율
- 과거 주가
- 배당 데이터

새로운 API를 추가하기 전에 현재 ExchangeRate.fun과 Gold API로 해결 가능한지 먼저 확인한다.

API 개수를 늘리는 것 자체를 목표로 하지 않는다.

# 30. 계산 가이드

'투자 가이드'가 아니라 **'계산 가이드'**라는 이름을 사용한다.

예:

- 평균매입단가란?
- 물타기/불타기 계산
- 목표 평균단가 계산
- 수익률 계산
- 손실 회복률
- CAGR
- 복리
- 적립식 투자
- 배당수익률
- ETF 보수
- 환율이 해외투자 수익률에 미치는 영향
- 세전 수익률과 세후 수익률
- 투자 세금 계산에서 과세연도가 중요한 이유
- 거래 수수료가 실제 수익률에 미치는 영향
- 포트폴리오 비중
- 리밸런싱

시장 전망이나 특정 종목 추천 콘텐츠를 만들지 않는다.

```text
│  └ CAGR
│
├ 장기투자
│  ├ 복리
│  ├ 적립식 투자
│  └ 목표자산
│
├ 배당
│  ├ 배당금/분배금
│  ├ 배당수익률
│  └ 목표 배당금

├ 세금·비용
```

# 41. 실제 개발 요청 시 작업 방식

이 프롬프트를 받았다고 전체 사이트를 바로 새로 작성하지 않는다.

먼저 기존 프로젝트를 분석한다.

순서:

1. 현재 기술 스택 및 디렉터리 구조 분석
2. 현재 기능 목록 작성
3. 기존 세금 계산 기능 및 계산 기준 분석
4. 재사용 가능한 코드 식별
5. V2.1 요구사항과 현재 구현 Gap 분석
6. 불필요하거나 중복된 기능 확인
7. Asset Type / Calculation Type / Context 분리 설계
8. Calculation Engine 설계
9. Exchange Rate Context 설계
10. Tax Rule 설계
11. Decimal/precision 정책 설계
12. Phase 1 변경 파일 목록
13. Phase 1 구현 순서
14. 기존 기능을 깨뜨리지 않는 방식으로 구현 시작

기존에 정상적으로 동작하는 기능을 이유 없이 다시 작성하지 않는다.

현재 기술 스택으로 충분히 구현 가능하다면 새로운 프레임워크로 불필요하게 마이그레이션하지 않는다.

대규모 리팩터링이 필요하다면 먼저 필요성과 영향범위를 설명한다.

**Phase 1부터 순차적으로 완성하며 Phase 1~7 전체를 한 번에 구현하지 않는다.**
