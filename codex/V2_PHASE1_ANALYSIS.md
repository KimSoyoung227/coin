# V2 Phase 1 분석 및 구현 설계

작성일: 2026-09-28 · 대상: v2 브랜치 · 기반 버전: 0.11.19 · Phase 1 개발 버전: 0.12.0

이 문서는 개편안 V2.1의 41번 작업 순서에 따라 기존 코드를 분석하고 Phase 1의 경계와 재사용 방침을 기록한다. 세법의 최신성을 확인하는 법률 검토 문서가 아니다. 아래 세금 정보는 저장소 구현의 현황이며 이번 단계에서 세율·지원 조건을 변경하지 않는다.

## 1. 현재 구조와 기능

| 영역 | 현재 구현 | 재사용 방침 |
|---|---|---|
| 런타임 | Python 3.9 이상, Flask 3.1, Jinja, ES module, CSS | 프레임워크 교체 없음 |
| 앱 조립 | `web.py`, `pages.py`, `api.py`, `security.py` | 별도 V2 Blueprint 추가, 기존 경로 보존 |
| 일반 계산 | `calculations.py`의 float 기반 수익률·양방향 동일 수수료·추가매수 평균단가, 금액→수량 | 기존 API 호환 유지; 새 대표 계산은 브라우저 엔진으로 분리 |
| UI | `index.html`, `app.js`, `style.css`; 수익/평균/세금 탭, 통화 선택 | 기존 6개 언어 화면 보존 |
| 세금 | `taxes.py`, `tax_ui.py`, `tax.html`, `tax.js`, `data/tax_rules.json` | 기존 계산·조건 그대로 연결 |
| 시세 | `market.py`, `/api/market-rates`, `rates.js` | 서버 캐시와 기존 공급자 유지 |
| 저장 | DB·회원 기능 없음; `session.js`가 탭별 sessionStorage에 최초 저장부터 1시간 보관 | 새 계산은 우선 메모리만 사용 |
| 언어·검색 | `localization.py`, `translations.json`; ko/en/zh/ja/es/de URL, canonical/hreflang, sitemap, robots; OG 없음 | 기존 SEO 회귀 검증, V2 URL 추가 |
| 검증 | Python unittest와 Node 테스트 | 기존 회귀 + 신규 엔진·페이지 테스트 |

기존 일반·세금 입력은 각각 `/api/calculate`, `/api/tax/calculate`로 전송된다. 코드에 DB 저장은 없지만 사이트 전체에 “브라우저 내에서만 사용”이라고 안내할 수는 없다. 신규 평균 계산에 한해 서버 전송 없는 동작을 명시하고, Privacy에서 기존 서버 계산과 탭 저장을 구분한다. 기존 광고 스크립트가 있는 화면도 있으므로 모든 방문 데이터가 외부 전송되지 않는다고 약속하지 않는다.

## 2. 기존 세금 계산 분석

- 지원 국가: 한국(KR), 미국(US), 일본(JP), 중국(CN), 독일(DE), 스페인(ES).
- 자산: stock / crypto; 국내·해외 조건을 별도로 조회한다. 신규 ETF/GOLD 등을 이 자산 목록에 임의 매핑하지 않는다.
- 저장된 규칙: 26개, 귀속연도 2026 및 일부 한국 암호자산 2027 규칙. 각 국가의 모든 자산이 2027을 지원하는 것은 아니다.
- 데이터 버전 `2026.09.24.1`, 기록된 최종 검증일 `2026-09-20`; active 20개, suspended 2개, review_required 2개, scheduled 2개.
- 규칙 식별키는 국가·연도·자산·국내/해외이고, JSON에 과세 거주자 유형, 소득 분류, 취득원가 방식, 과세 이벤트, 적용기간, 세율·공제, 공식 출처가 있다.
- 계산은 Python Decimal, 내부 precision 50, 입력 소수 자릿수와 크기 제한, 출력 소수 둘째 자리 ROUND_HALF_UP을 사용한다.
- 계산 결과에 세목, 계산 과정, 공제/과세표준, 버전, 검증일, 출처 및 경고가 포함된다. 미지원 연도·특수 조건·원가 미확인 등은 검토 필요 상태를 사용한다.
- 이미 중앙 규칙 모델이 있으므로 Phase 4는 상품 세부유형·공통 Context와의 연결을 중심으로 확장한다. 국가별 분기 및 일부 UI 조건은 코드에 남아 있으므로 규칙과 UI 메타데이터의 경계를 점검한다.
- Phase 1에서 세금 조건은 수정하지 않는다. 향후 수정 시 공식기관 자료 재검증과 조건별 필수입력 문서 동시 갱신이 필요하다.

## 3. 기존 API 분석

| 항목 | ExchangeRate.fun | Gold API |
|---|---|---|
| 호출 위치 | `market.py` `_load_currencies` | `_fetch_price`, `_load_metals`, `_load_bitcoin` |
| URL | `https://api.exchangerate.fun/latest?base=USD` | `https://api.gold-api.com/price/{symbol}/KRW` |
| 소비 응답 | `rates.KRW`, CNY/JPY/EUR/GBP, USD=1 | `price`, `updatedAt` |
| 정규화 | KRW / 각 통화의 USD 기준 값 = 통화 1단위당 원화 | 금·은 troy oz → g, 구리 pound → g, BTC는 1개당 KRW |
| 원래 단위 상수 | 해당 없음 | 31.1034768 g/oz, 453.59237 g/lb |
| 서버 TTL | 3600초 | 금속 300초, BTC 60초 |
| 화면 | 기존 시세 표, 사용자가 고른 기준통화로 재환산 | 같은 표; 계산 입력값 자동 대체 없음 |
| 시각 | 조회 완료 `completed_at`; 공급자 기준시각 미수집 | 조회 완료 + 심볼별 `source_updated_at` 수집 |

- 브라우저는 진입 직후와 60초마다 `/api/market-rates`를 호출하며 수동 새로고침도 지원한다. 통화 표시 변경은 메모리의 마지막 응답만 다시 그린다.
- 서버 프로세스별 그룹 캐시·Lock으로 같은 그룹의 중복 갱신을 줄인다. 금속 3종과 각 그룹은 병렬 조회한다. 여러 워커 사이에는 캐시가 공유되지 않는다.
- 최초 스냅샷은 환율 1회, 금속 3회, BTC 1회가 필요하다. 이후 TTL 내에는 외부 호출 없이 반환한다. 실제 호출 빈도는 요청 빈도·워커 수·실패 여부에 좌우된다.
- 요청당 8초 제한, 256KiB 응답 제한, JSON 객체와 유한한 양수 검증이 있다.
- 갱신 실패 시 기존 데이터에 `stale=true`를 붙인다. 최초 실패 그룹은 `errors`에 포함하고 나머지 그룹은 반환한다. 전부 없으면 HTTP 503이다. 실패 재시도 backoff 및 stale 최대 보관기간은 없다.
- 브라우저는 같은 origin의 Flask만 호출하고 Flask가 외부에 요청하므로 외부 공급자의 브라우저 CORS 정책에 직접 의존하지 않는다. CSP의 connect-src에도 공급자를 추가할 필요가 없다.
- 기존 화면은 그룹별 조회 완료시각과 stale 여부를 표시한다. Gold의 공급자 기준시각은 수집하지만 화면에 표시하지 않는다. 환율의 조회시각을 데이터 기준시각으로 해석해서는 안 된다.
- 이 분석은 코드 기준이다. 외부 서비스의 현재 응답·요금·갱신주기·가동 상태를 실호출로 검증한 결과는 아니다.

공급자 추상화는 Phase 1 계산 엔진의 의존성으로 넣지 않는다. 이후 현재 MarketService를 adapter로 감싸 provider / symbol / value / currency / unit / dataTimestamp / retrievedAt / stale을 가진 DTO를 반환한다. 환율은 base / quote / rate를 함께 반환하고 기준시각을 알 수 없으면 null로 둔다. 현재값과 과거값 조회 capability는 구분하고 지원하지 않는 과거 조회를 최신값으로 대체하지 않는다.

## 5. 공통 설계

- Asset: 안정적인 ID, 표시명, 기본 통화, 수량단위, 가격 표시 자릿수, 수량 자릿수/거래단위를 가진다. 환율·배당·ETF 비용 지원 capability는 향후 확장 설계이며 Phase 1 모델에 구현된 플래그는 아니다. 국내/해외 주식, ETF, GOLD, CRYPTO, OTHER를 UI와 엔진이 공유한다. 국내상장 여부는 ETF 자산 ID를 새로 만드는 대신 상품 Context로 확장한다.
- Calculation Type: 평균매입 / 목표 평균 / 추가매수 시나리오를 Asset에서 독립시킨다. 순수 함수가 입력을 검증하고 결과를 반환하며 DOM·fetch·저장소를 참조하지 않는다.
- Exchange Rate Context: 매수/평가/매도 각각 rate, base, quote, 적용일, 수동/참고값 출처와 공급자 기준·조회시각을 가진다. API 사용은 선택이고 적용은 사용자 동작으로 한정한다.
- Fee Context: 매수·매도별 실제 금액 또는 수수료율, 기타 비용을 명시한다. 증권사 기본 요율은 추정하지 않는다.
- Tax Rule: 기존 국가+연도+자산+시장 규칙을 보존하고 상품유형·거래/소득 유형·규칙 버전으로 확장한다. 일반 Asset 모델에 세율을 넣지 않는다.
- Presentation: 입력 → 핵심 결과 → 세부 결과/공식 → 시나리오 표 → 그래프. 그래프는 계산 결과를 시각화할 뿐 원 계산에 반영하지 않으며 표를 함께 제공한다.

### 정밀도 정책

신규 엔진은 외부 라이브러리를 추가하지 않는 BigInt 기반 유리수 연산으로 중간 정밀도를 보존한다. 원문 입력 문자열을 직접 검증하며 금액·수량을 Number로 먼저 변환하지 않는다. 입력·출력 소수 자릿수는 최대 18자리, 입력 필드 값은 1e24 미만이며 화면 표시 자릿수와 분리한다. 출력 반올림은 절댓값 기준 HALF_UP이다. Crypto 0.00000001을 허용한다. 목표 역산 수량은 자산 거래단위에 맞춰 올림하고, 실제 올림 수량으로 투자금·최종 평단가를 재계산한다. 목표가가 현재 평균단가와 같으면 이미 달성한 조건으로 추가수량 0을 반환하며 추가 매수가도 같은 경우를 허용한다. 이 경우를 제외하고 추가 매수가와 목표가가 같거나 목표가가 현재 평균단가와 추가매수가 사이에 있지 않으면 달성 불가로 거부한다. 차트 좌표에만 표시용 Number를 사용한다. 구체적인 한도와 반올림 동작은 `v2-engine.js`와 경계값 테스트를 기준으로 한다.

공유 코드 충돌을 피하기 위해 문서 / 엔진 / UI / 통합·검증을 분담한다. 엔진 인터페이스 합의 후 UI를 연결하고 통합 담당자가 전체 검증을 수행한다.

V2 홈은 `/v2/`에서 먼저 검토한다. `/`의 기존 언어 리다이렉트 및 6개 언어 화면은 유지한다. 신규 대표 계산 경로는 `/calculator/average-price`, `/calculator/target-average`, `/calculator/additional-buy`; 정책 경로는 `/about`, `/privacy`, `/disclaimer`다. 세금과 기존 수익 기능에는 기존 화면으로 연결한다. 아직 없는 Phase 2 이후 기능을 사용 가능한 계산기로 표시하지 않는다.

## 7. 검증 및 사용자 검토

- 정밀 계산: 일반 정수, 소수, Crypto 최소 단위, 큰 입력, 0/음수/잘못된 형식, 목표 달성 불가, 거래단위 올림, 추가매수 금액·수량 결과 일관성.
- 페이지: 정상 URL, 기본 메타데이터, 정책 링크, 기존 언어 경로/세금 API 보존, sitemap 및 보안 헤더.
- UX: 입력 변경 시 결과 정합성, 표와 그래프의 동일 데이터, 모바일 가로 넘침, 키보드·레이블·오류 안내.
- 회귀: 기존 Python 및 Node 테스트를 실행하고 실제 실행 결과는 WORK_LOG에 기록한다. 이 분석 문서 자체는 테스트 통과를 주장하지 않는다.
- 각 개발 모듈을 검증한 뒤 사용자에게 검토를 요청한다. Phase 1 결과의 자산별 기본 단위, 목표수량 올림 설명, 모바일 결과 표현, `/v2/`에서 기존 메인으로의 전환 여부를 검토 대상으로 제시한다. Phase 2~7을 한 번에 진행하지 않는다.
