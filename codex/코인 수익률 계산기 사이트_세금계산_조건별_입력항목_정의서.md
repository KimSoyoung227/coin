# 세금 계산 조건별 입력항목 정의서

- 작성일: 2026-09-24
- 기준: 현재 작업 디렉터리의 v0.11.19 입력·계산 구현. 세법 자체의 필수 신고항목이 아니라 이 프로젝트의 화면·계산 동작을 정리한 문서이다.
- 범위: 취득 내역, 처분 내역, 연간 소득 및 세부 조건의 전체 입력항목.
- 거래구분은 국내/해외를 의미한다. 암호자산은 거래구분 선택을 숨기며 내부적으로 해외 값을 사용한다. 매도/교환/결제는 별도의 **처분 유형**이다.

## 1. 표 읽는 방법

| 표시 | 의미 |
|---|---|
| 필수 | 화면에서 빈칸 제출을 막는 항목 |
| 선택 | 빈칸 또는 미체크로 제출할 수 있는 항목. 기본값·계산 영향은 비고 참조 |
| 조건부 필수 | 통화·취득일·처분 유형 등 추가 조건에 따라 화면에서 필수 |
| 계산 필요 | 화면에서는 선택이지만 세액 산출 또는 범위가 아닌 단일 추정값 산출에 필요한 항목 |
| 숨김 | 화면에서 숨기고 요청·화면 검증에서 제외 |

화면 필수와 계산 필요는 다르다. 특히 연간 소득 및 세부 조건에는 HTML `required` 항목이 없지만, 계산 단계에서는 입력 또는 체크를 요구하는 항목이 있다. 체크박스의 ‘필요’는 체크해야 한다는 뜻이다.

## 2. 표시 우선순위 및 지원 조건

### 2.1 우선 적용 규칙

아래 규칙을 먼저 적용한 뒤 3~5절의 개별 항목 표를 적용한다. ‘전체’는 이 우선 규칙으로 숨기지 않은 지원 조합을 뜻한다.

| 우선 조건 | 취득·처분 영역 | 연간 조건 영역 | 계산 버튼·안내 |
|---|---|---|---|
| 중국 암호자산 | 현재 선택지에서 제외; 방어 로직상 숨김 | 숨김 | 계산 차단·검토 필요. 비과세로 판정하지 않음 |
| 특수 거래 체크 | 모두 숨김 | 모두 숨김 | 버튼·입력 도움말 숨김, 검토 필요 안내. 아래 비과세 조건보다 우선 |
| 한국 암호자산 + 2026년 | 모두 숨김, 처분 유형도 숨김 | 모두 숨김 | 버튼·입력 도움말 숨김, 과세 시행 전 안내 |
| 일본 주식 + NISA 적격 체크 | 모두 숨김 | 해제할 수 있도록 NISA 체크만 표시 | 버튼·입력 도움말 숨김, 적격 양도차익 비과세 안내 |
| 나머지 지원 조합 | 개별 항목 규칙 적용 | 개별 항목 규칙 적용 | 계산 유지 |

미지원 국가·연도는 정상 과세 계산 대상으로 보정하지 않는다. UI는 지원 선택지를 제공하고, API의 미지원 규칙 요청은 검토 필요를 반환한다. 비과세 응답에는 입력받지 않은 실현손익·세후 금액을 임의의 0으로 생성하지 않는다.

### 2.3 통화·환율 공통 규칙

| 거래 조건 | 취득·처분 통화 | 취득·처분 환율 |
|---|---|---|
| 국내주식 | 입력 숨김, 거주 국가 기준 통화 자동 적용 | 입력 숨김, 1 적용 |
| 해외주식·암호자산, 거래 통화 = 기준 통화 | 통화 선택 필수 | 입력 숨김, 1 적용 |
| 해외주식·암호자산, 거래 통화 ≠ 기준 통화 | 통화 선택 필수 | 해당 거래일의 양수 환율 필수 |

| 국가 | 한국 | 미국 | 일본 | 중국 | 독일 | 스페인 |
|---|---|---|---|---|---|---|
| 기준 통화 | KRW | USD | JPY | CNY | EUR | EUR |

각 취득 행과 처분의 통화를 독립적으로 비교한다. 국내주식 금액은 제목 옆의 기준 통화로 입력하며 기존 금액을 자동 환전하지 않는다. 해외 거래의 통화·환율 초안은 보존하고 해외로 돌아가면 복원한다.

## 3. 취득 내역

각 취득 내역 행에 개별 적용한다. 취득 내역은 1~50개를 받는다.

| 입력항목 | 필드 | 국가·자산·거래구분 조건 | 화면 필수 여부 | 계산 조건·빈칸 처리 |
|---|---|---|---|---|
| 취득일 | `buy_date` | 전체 | 필수 | 처분일 이후는 불가 |
| 취득 잔여 수량 | `quantity` | 전체 | 필수 | 0보다 커야 함 |
| 취득 총액 | `amount` | 전체 | 필수 | 잔여 수량에 대응하는 총액; 0 입력 가능 |
| 거래 통화 | `currency` | 해외주식·암호자산 | 필수 | 국내주식은 2.3절에 따라 자동 적용 |
| 거래일 환율 | `fx` | 해외주식·암호자산, 해당 취득 행의 거래 통화 ≠ 국가 기준 통화 | 조건부 필수 | 양수 필요; API에 환율이 없으면 검토 필요 |
| 거래일 환율 | `fx` | 해외주식·암호자산, 해당 취득 행의 거래 통화 = 국가 기준 통화 | 숨김 | 환율 1 적용 |
| 직접 수수료 | `fee` | 전체 | 선택 | 빈칸은 0; 수수료 반영됨 체크 시 읽기 전용이며 별도 가산하지 않음 |
| 총액에 수수료 반영됨 | `fees_included` | 전체 | 선택 | 기본 체크(true). 사용자가 해제하면 false; 저장된 해제 상태는 복원 시 유지 |
| 2026-12-31 시가 총액 (KRW) | `transition_value` | 한국 + 암호자산 + 2027년, 취득일 < 2027-01-01 | 조건부 필수 | 환산 취득원가와 이 가액 중 큰 값 사용 |
| 2026-12-31 시가 총액 (KRW) | `transition_value` | 한국 + 암호자산 + 2027년, 취득일 ≥ 2027-01-01 | 숨김 | 계산에 사용하지 않으므로 표시·전송하지 않음 |
| 2026-12-31 시가 총액 (KRW) | `transition_value` | 그 외 조합 | 숨김 | 사용하지 않음 |

취득일이 빈칸이면 경과가액을 숨기지만, 취득일 자체가 필수이므로 제출 전 날짜를 입력해야 한다.

## 4. 처분 내역

| 입력항목 | 필드 | 국가·자산·거래구분 조건 | 화면 필수 여부 | 계산 조건·빈칸 처리 |
|---|---|---|---|---|

| 처분 수량 | `sell_quantity` | 전체 | 필수 | 0 초과, 취득 잔여 수량 합계 이하 |
| 처분 총액 / 받은 자산 시가 | `sell_amount` | 전체 | 필수 | 0 입력 가능 |
| 거래 통화 | `sell_currency` | 해외주식·암호자산 | 필수 | 취득 통화와 독립적으로 선택; 국내주식은 자동 적용 |

| 교환한 원래 자산의 시가 (자국통화) | `swap_given_value` | 그 외 조합·처분 유형 | 숨김 | 사용하지 않음 |

## 5. 연간 소득 및 세부 조건

**모든 항목이 화면에서는 선택 입력이다.** 아래의 ‘계산 필요 여부’는 입력을 생략했을 때 계산이 가능한지 구분한다. 명시된 표시 조건 외에는 숨김이다. 금액은 국가 기준 통화로 입력하며, 화면 숫자 입력의 `0` 자리표시는 실제 입력값이 아니다.

### 5.1 공통 및 연간 손익

| 입력항목 | 필드 | 표시 조건 | 계산 필요 여부 및 미입력 영향 |
|---|---|---|---|
| 취득원가와 손실상계 조건을 확인함 | `basis_confirmed` | 전체 | **계산 필요**. 미체크 시 거래 금액 계산 전에 검토 필요 반환 |
| 해당 분류의 연간 손익을 모두 입력함 | `annual_complete` | 전체 | 독일 암호자산은 **계산 필요**. 미체크 시 검토 필요. 나머지는 미체크로 계산하되 부분 계산 안내 |
| 해외 납부세액 (자국통화) | `foreign_tax` | 전체 | 선택, 빈칸 0. 양수면 외국납부세액 공제 검토 안내, 공제 후 세액·세후 금액 미산출 |
| 기타 동일 분류 연간 이익 | `other_gains` | 한국·일본·중국·독일·스페인, 모든 자산·거래구분 | 선택, 빈칸 0. 중국 해외 주식에서는 이 항목 숨김. 비과세·차단 조건은 2.1절 적용 |
| 통산 가능한 동일 분류 손실 | `other_losses` | 한국·일본·중국·독일·스페인, 모든 자산·거래구분 | 선택, 빈칸 0. 중국 해외 주식에서는 이 항목 숨김. 비과세·차단 조건은 2.1절 적용 |
| 기타 순단기자본손익 (손실은 음수) | `other_short` | 미국, 주식·암호자산, 국내/해외 공통 | 선택, 빈칸 0; 음수 허용 |
| 기타 순장기자본손익 (손실은 음수) | `other_long` | 미국, 주식·암호자산, 국내/해외 공통 | 선택, 빈칸 0; 음수 허용 |

중국 해외 주식은 이번 처분 손익만 계산하므로 기타 연간 이익·손실을 전송하지 않는다. 일본 NISA는 손익 계산 자체를 생략한다. 숨긴 입력의 초안은 보존한다.

| 일반 소액주주 적격 장내 상장주식인가요? | `eligible` | 중국 + 주식 + 국내 | **계산 필요: 예 선택**. 그 외에는 검토 필요 |

| NISA 적격 계좌·주식 | `nisa` | 일본 + 주식 + 국내/해외 | 선택. 체크하면 금액·취득원가 확인 없이 NISA 비과세 안내; 미체크는 일반 주식 계산 |
| 기타 순저축소득 (손실상계 후) | `other_savings` | 스페인 + 주식/암호자산 + 국내/해외 | 선택. 빈칸은 0으로 계산하되 부분 계산 안내 |

미국은 신고 상태·다른 과세소득·MAGI·기타 순투자소득이 모두 있어야 일반적으로 세액 범위 대신 단일 추정값을 제공한다. 독일 암호자산은 연간 손익 확인 체크가 면세한도 판정보다 먼저 요구된다.

### 5.3 입력항목의 정의와 작성 방법

이 절은 **현재 계산기가 각 입력값을 어떤 의미로 받아 사용하는지** 설명한다. 국가별 세법의 모든 신고요건을 정의하는 문서는 아니다. 표시·필수 여부는 5.1~5.2절, 비과세 시 입력 생략은 2절의 우선 적용 예외를 따른다.

공통 입력 원칙:

- 금액은 선택한 거주 국가의 기준 통화(KRW/USD/JPY/CNY/EUR)로 입력한다. 취득·처분에서 선택한 거래 통화와 다를 수 있다.
- ‘기타’ 또는 ‘이 계산 제외’는 이 화면에서 계산에 반영하는 손익과 중복되지 않는 금액을 뜻한다. 연간 합계를 이미 포함한 금액을 다시 더하지 않는다.
- 손실은 원칙적으로 양수로 입력한다. 단, 미국의 `other_short`, `other_long`은 순손익이므로 손실이면 음수로 입력한다.
- 빈칸과 숫자 `0`은 다르다. 다른 소득·MAGI 등이 없음을 확인했다면 `0`을 입력한다. 숫자 칸에 보이는 회색 `0`은 자리표시이며 입력값이 아니다.
- 아래 예시는 항목의 의미를 설명하기 위한 가정이다. 거래별 손익·원가·상계 가능 여부를 확인한 값으로 입력한다.

#### A. 투자자 자격 및 시장

| 화면 항목 / 필드 | 정의 | 입력 방법·예시 | 계산에 미치는 영향 |
|---|---|---|---|
| 일반 소액주주 적격 장내 상장주식인가요? / `eligible` | 해당 거래가 이 계산기의 일반 소액주주·적격 상장시장 거래 범위에 해당하는지 확인하는 항목. 단순히 거래금액이 작다는 뜻은 아니다. | 적용 조건을 확인했다면 ‘예’, 해당하지 않으면 ‘아니요’, 확인하지 못했다면 ‘확인 필요’를 선택한다. | 한국은 미확인 시 일반 거래 가정 안내 후 계산하고 ‘아니요’면 별도 검토한다. 중국 국내주식은 ‘예’여야 일반 계산을 진행한다. |
| 상장시장 / `stock_market` | 처분한 국내주식에 적용할 시장별 거래세 규칙을 선택하는 항목. 증권사 이름을 입력하는 곳이 아니다. | 한국은 KOSPI·KOSDAQ·KONEX, 중국은 SSE(상하이)·SZSE(선전) 중 실제 거래에 맞는 시장을 선택한다. | 한국의 시장별 거래세·농특세, 중국의 지원시장 여부를 결정한다. 국가와 맞지 않는 시장이나 빈 선택은 검토 필요로 처리한다. |

#### B. 연간 손익 및 다른 소득

| 화면 항목 / 필드 | 정의 | 입력 방법·예시 | 계산에 미치는 영향 |
|---|---|---|---|
| 기타 동일 분류 연간 이익 / `other_gains` | 이번 화면의 처분 외에 같은 과세연도·통산 가능한 과세 분류에서 발생한 이익의 합계. 매도대금 전체가 아니다. | 다른 거래의 이익이 100만 원, 손실이 30만 원이면 이 칸에는 `1000000`, 손실 칸에는 `300000`을 입력한다. 독일 암호자산은 계산 대상이 되는 다른 단기 사적 양도거래 이익도 확인한다. | 이번 손익에 더해 연간 손익을 계산한다. 이미 순액으로 정리한 값에 같은 손실을 다시 차감하지 않도록 주의한다. 빈칸은 0이다. |
| 통산 가능한 동일 분류 손실 / `other_losses` | 이번 화면의 처분 외에 같은 분류의 이익과 상계할 수 있다고 확인한 손실의 합계. 모든 투자 손실을 무조건 합산하는 항목은 아니다. | 상계 가능한 손실이 30만 원이면 양수 `300000`을 입력한다. 현재 처분의 손실은 자동 계산되므로 중복 입력하지 않는다. | 연간 손익에서 차감한다. 손실의 상계 자격이나 이월 가능 여부 자체를 자동 판정하지 않는다. 빈칸은 0이다. |
| 기타 순단기자본손익 (손실은 음수) / `other_short` | 미국 계산에서 이번 거래 외의 단기 자본이익과 손실을 합산한 순액. | 다른 단기 거래의 이익 2,000달러와 손실 500달러라면 `1500`, 순손실 500달러라면 `-500`을 입력한다. | 이번 거래의 단기 손익에 합산하고 장기 손익과 상계한다. 빈칸은 0이다. |
| 기타 순장기자본손익 (손실은 음수) / `other_long` | 미국 계산에서 이번 거래 외의 장기 자본이익과 손실을 합산한 순액. | 증권사 자료 등으로 장기 분류를 확인한 순이익 3,000달러는 `3000`, 순손실 1,000달러는 `-1000`을 입력한다. | 이번 거래의 장기 손익에 합산하고 단기 손익과 상계한 후 장기이득 세율 계산에 사용한다. 빈칸은 0이다. |
| 다른 과세소득 (공제 후, 이 계산 이익 제외) / `other_income` | 이 계산에서 산출하는 투자이익을 더하기 전의 다른 과세소득. 연봉·매출·통장 입금액 전체를 뜻하지 않는다. | 공제 후 다른 과세소득이 30,000달러라면 `30000`을 입력한다. 미국에서는 다른 일반 과세소득을 기준으로 하며, 별도 자본손익 칸에 반영한 이익을 중복 포함하지 않는다. 일본·독일 암호자산에서도 계산할 이익을 제외한 과세소득을 사용한다. | 기존 소득 위에 투자이익을 더해 누진세 증가분을 계산한다. 미국·일본은 빈칸이면 범위 추정, 독일은 과세 대상 단기이익이 있는 분기에서 검토 필요가 된다. |

#### C. 미국 신고 및 순투자소득세 조건

| 화면 항목 / 필드 | 정의 | 입력 방법·예시 | 계산에 미치는 영향 |
|---|---|---|---|
| 미국 신고 상태 / `filing` | 적용할 미국 연방소득세 신고 유형. 결혼 여부만으로 자동 결정되는 항목은 아니다. | 실제 적용되는 독신·부부 공동신고·부부 개별신고·세대주 중 선택한다. 화면의 공동 유형은 ‘부부 공동과세’로 표시된다. | 일반소득·장기이득의 세율 구간, NIIT 기준액, 손실공제 한도를 선택한다. 미선택이면 단일 추정값 대신 세액 범위를 제공한다. |
| 이 계산 손익 제외 MAGI / `magi` | MAGI(Modified Adjusted Gross Income, 수정조정총소득)를 NIIT 계산에 쓰기 위한 기준값. 이 도구에서는 이 계산에 반영할 투자손익을 제외한 기준 금액을 받는다. | 계산 대상 손익을 제외한 MAGI가 190,000달러라면 `190000`을 입력한다. 공제 후 과세소득인 `other_income`과 같은 값이라고 가정하지 않는다. | NIIT 소득 기준 초과액을 구한다. 도구가 추가하는 양의 순자본손익을 미리 중복 포함하지 않는다. 빈칸이면 NIIT를 포함한 세액 범위를 제공한다. |
| 이 계산 제외 기타 순투자소득 / `other_investment` | NIIT 계산에서 사용할 기존 순투자소득. 이 계산에 반영하는 자본손익을 제외하고, 다른 투자소득에서 관련 공제 등을 반영한 값이다. | 이번 자본손익 외의 대상 이자·배당 등 순투자소득이 5,000달러라면 `5000`, 없다면 `0`을 입력한다. | MAGI 초과액과 함께 계산 전·후 NIIT 차이를 산출한다. 기타 단기·장기손익 칸에 반영한 금액을 다시 중복 포함하지 않는다. 빈칸이면 범위 추정이다. |

이 도구의 미국 계산은 기본 입력에 다른 단기·장기손익을 합산한 자본손익 전체를 계산 대상으로 삼는다. MAGI·기타 순투자소득·다른 과세소득의 기준값과 별도 자본손익 입력 사이에 같은 이익이 중복되지 않아야 한다. MAGI를 과세소득에서 역산하거나 NIIT용 순투자소득을 자동 산출하는 기능은 없다.

#### D. 공제·계좌·국가별 추가 조건

| 화면 항목 / 필드 | 정의 | 입력 방법·예시 | 계산에 미치는 영향 |
|---|---|---|---|
| 남은 연간 공제액 (빈칸: 전액) / `deduction_remaining` | 이 계산에 적용할 연간 공제의 미사용 잔액. 다른 계산에서 이미 사용한 공제와 중복 적용하지 않기 위한 항목이다. | 다른 계산에서 사용하고 100만 원이 남았다면 `1000000`, 이미 모두 사용했다면 `0`을 입력한다. | 계산 대상 연간 손익에서 차감한다. 빈칸은 규칙상 전액을 적용하므로 ‘공제 없음’은 반드시 0을 입력한다. 독일 주식은 공동과세 여부에 따라 전액 한도가 달라진다. |

### 8.1 항목 유지·삭제 판정

현재 취득 8개·처분 8개·연간 조건 20개 입력은 모두 적어도 한 지원 조건에서 사용된다. 사용 조건과 역할은 3~5절에 정의하므로 별도 중복 목록은 두지 않는다. 특정 조합에서 불필요한 항목은 숨기고, 모든 조합에서 미사용인 항목만 삭제한다.

이미 화면에서 제거된 지갑 이전 선택의 미사용 번역 키 `taxTransferOption`은 6개 언어에서 삭제했다. 기존 API 호환 분기와 혼동하지 않는다.

## 9. 입력 계약 보완 (v0.11.19)

- 스페인 암호자산 교환: 포함 체크 시 `sell_amount`는 받은 자산 시가에서 수수료를 뺀 금액, 해제 시 차감 전 시가이다. `sell_fee`는 두 경우 모두 거래 통화로 필수 입력(없으면 0). `swap_given_value`는 항상 자국통화의 차감 전 시가이다. 예: 받은·원래 자산 각각 20,000 EUR, 수수료 1,000 EUR이면 체크한 총액 19,000과 해제한 총액 20,000의 순처분액은 모두 19,000이다.
- 동일 취득일 FIFO는 입력 행 순서대로 배분한다. 해당일의 실제 취득 순서에 맞춰 입력한다.
- 수수료 포함 기본 true·국내주식 통화 자동 적용은 화면 동작이다. 직접 API는 체크 누락 시 false이며 거래 통화를 명시해야 한다.
- 일본 암호자산 기타 과세소득 누락 시에도 해외 납부세액과 공제 검토 안내를 유지한다. 세액은 범위로 제공하며 공제 후 금액은 미확정이다.
